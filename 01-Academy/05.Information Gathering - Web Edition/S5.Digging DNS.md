## Digging DNS

## DNS recon tools
| Tool | Use |
|---|---|
| **dig** | Versatile queries (any record), zone transfers, detailed output — the go-to |
| nslookup | Simple A/AAAA/MX lookups |
| host | Quick concise A/AAAA/MX |
| **dnsenum** | Automated enum: subdomain brute-force, dictionary, zone transfer |
| fierce | Subdomain enum, recursive + wildcard detection |
| dnsrecon | Combines techniques, multiple output formats |
| theHarvester | OSINT — emails/employees/subdomains from many sources |

## dig commands (cheat sheet)
```bash
dig domain.com              # default A record
dig domain.com A            # IPv4
dig domain.com AAAA         # IPv6
dig domain.com MX           # mail servers
dig domain.com NS           # authoritative name servers
dig domain.com TXT          # TXT (SPF, verifications, tech leaks)
dig domain.com CNAME        # alias
dig domain.com SOA          # zone admin info
dig domain.com ANY          # all records (often refused, RFC 8482)
dig @1.1.1.1 domain.com     # query a specific resolver
dig +trace domain.com       # full resolution path (root->TLD->auth)
dig -x 192.168.1.1          # reverse lookup (IP -> hostname)
dig +short domain.com       # just the answer
dig +noall +answer domain.com   # only the answer section
```

## Reading dig output
- **Header** — `status: NOERROR` (success), flags: `qr`=response, `rd`=recursion desired, `ad`=authentic; counts of question/answer/authority/additional.
- **Question** — what you asked (`;google.com. IN A`).
- **Answer** — the result + **TTL** (cache lifetime): `google.com. 0 IN A 142.251.47.142`.
- **Footer** — query time, which `SERVER` answered + protocol, timestamp, msg size.
- **OPT pseudosection** = EDNS (bigger messages, DNSSEC).

## Notes to self
- Fast recon combo: `dig +short domain NS`, `dig +short domain MX`, `dig domain TXT`, then try `dig axfr @<ns> domain` (zone transfer).
- `+short` / `+noall +answer` to script cleanly; `@<resolver>` to pick the server (query the target's own NS).
- **Rate-limit awareness** — servers can detect/block excessive queries; get permission before heavy DNS recon.
- `dig -x <ip>` reverse lookups can reveal hostnames/other vhosts on shared infra.
