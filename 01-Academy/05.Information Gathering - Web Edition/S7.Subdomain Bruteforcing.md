## Subdomain Bruteforcing

Active discovery: test a **wordlist** of candidate names against the domain, keep the ones that resolve.

## Process (4 steps)
1. **Pick a wordlist** — general-purpose (dev, staging, admin, mail…), targeted (industry/tech-specific), or custom.
2. **Iterate** — append each word to the domain → `dev.example.com`, `staging.example.com`…
3. **DNS lookup** — query each (A/AAAA); resolves = exists.
4. **Filter/validate** — keep resolving names; confirm by browsing.

## Tools
| Tool | Note |
|---|---|
| **dnsenum** | Perl toolkit: records, zone transfer, brute-force, Google scrape, reverse/WHOIS |
| fierce | Recursive, wildcard detection, easy |
| dnsrecon | Combines techniques, flexible output |
| **amass** | Actively maintained, many data sources, integrations |
| assetfinder | Quick lightweight passive-ish discovery |
| **puredns** | Fast mass-resolver + filtering (good with big lists) |

## dnsenum
```bash
dnsenum --enum inlanefreight.com \
  -f /usr/share/seclists/Discovery/DNS/subdomains-top1million-20000.txt -r
```
- `--enum` — tuning shortcut.
- `-f <wordlist>` — SecLists subdomain list (here top 20k).
- `-r` — **recursive** (enumerate subdomains of found subdomains).
- Also auto-does: DNS records (A/NS/MX/TXT), **zone-transfer attempt**, Google scrape, reverse lookup.

## Notes to self
- Common SecLists lists: `subdomains-top1million-5000/20000/110000.txt` under `/usr/share/seclists/Discovery/DNS/`.
- Watch for **wildcard DNS** (everything resolves → false positives); `fierce`/`puredns` detect it.
- Faster alternatives for big lists: `puredns bruteforce <wl> domain -r resolvers.txt`, or `ffuf -u http://FUZZ.domain -w <wl>`.
- Active = detectable; pair with passive (crt.sh/amass) for coverage.
