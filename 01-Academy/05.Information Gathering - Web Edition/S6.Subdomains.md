## Subdomains

Extensions of the main domain (`blog.`, `shop.`, `mail.example.com`) separating sections/functions. Often host things **not linked from the main site**.

## Why they matter (high-value targets)
- **Dev/staging environments** — relaxed security, vulns, leaked info.
- **Hidden login portals** — admin panels not meant to be public.
- **Legacy apps** — old, forgotten, unpatched software.
- **Sensitive info** — exposed docs, internal data, config files.

## Enumeration — two approaches
From DNS, subdomains = **A/AAAA** records (sometimes **CNAME** aliases).

### Active — interact with the target's DNS
- **Zone transfer** (`dig axfr`) — a misconfigured NS leaks the whole list. Rare now, but always try.
- **Brute-force** — test a wordlist of subdomain names against the domain. Tools: **dnsenum, ffuf, gobuster**.
- More control / comprehensive, but **more detectable**.

### Passive — external sources, no direct queries
- **Certificate Transparency (CT) logs** — public SSL/TLS cert repos; the **SAN** field lists subdomains (e.g. crt.sh).
- **Search engines** — `site:` operator to filter subdomains.
- **Aggregated DNS databases/tools** — search without touching the target.
- **Stealthier**, but may miss some subdomains.

## Notes to self
- **Combine both** — passive (CT logs, crt.sh) for a free list, then active brute-force to fill gaps.
- Always try `dig axfr @<ns> domain` first — instant full list if misconfigured.
- Brute-force syntax reminders: `gobuster dns -d domain -w wordlist`, `ffuf -u http://FUZZ.domain -w wordlist` (or Host-header fuzzing for vhosts).
- crt.sh one-liner: `curl -s 'https://crt.sh/?q=%25.domain.com&output=json' | jq -r '.[].name_value' | sort -u`.
