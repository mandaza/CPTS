## DNS

Translates human-readable **domain names → IP addresses**. The internet's "GPS."

## Resolution flow (relay race)
1. **Computer** checks local cache → asks a **DNS resolver** (usually ISP).
2. Resolver checks its cache → if miss, does a **recursive lookup**:
3. **Root server** (13 worldwide, a–m) → points to the right **TLD server** (.com, .org).
4. **TLD server** → points to the domain's **authoritative name server**.
5. **Authoritative NS** holds the real **A record** → returns the IP.
6. Resolver caches it and hands it back → computer connects.

## Hosts file (manual override, bypasses DNS)
- Linux/Mac: `/etc/hosts` · Windows: `C:\Windows\System32\drivers\etc\hosts`
- Format: `<IP>  <hostname> [alias...]` — edit as root/admin, takes effect immediately.
- Uses: point a domain to a local dev server, test by IP, or block (`0.0.0.0 unwanted-site.com`).
- **Pentest relevance:** add the box's vhosts here (e.g. `10.129.x.x target.htb`) so they resolve.

## Zones & records
- **Zone** = part of the namespace one admin manages (a domain + its subdomains). Defined in a **zone file** on the DNS server.
- Classes: records show **`IN`** = Internet (CH/HS exist but rare).

| Record | Purpose |
|---|---|
| **A** | hostname → IPv4 |
| **AAAA** | hostname → IPv6 |
| **CNAME** | alias → another hostname |
| **MX** | mail server(s) for the domain |
| **NS** | delegates the zone to an authoritative name server |
| **TXT** | arbitrary text — SPF, domain verification, service hints |
| **SOA** | zone admin info (primary NS, responsible email, serial, timers) |
| **SRV** | host + port for a specific service |
| **PTR** | reverse: IP → hostname (`in-addr.arpa`) |

## Why DNS matters for recon
- **Uncover assets** — subdomains, mail servers, NS. A CNAME to an old box (`dev` → `oldserver`) = potential vuln / subdomain takeover.
- **Map infrastructure** — NS reveals hosting provider; names like `loadbalancer`/`vpn` pinpoint systems & entry points.
- **Monitor changes** — new subdomain (`vpn.example.com`) = new entry point; TXT like `_1password=...` reveals tech in use → phishing/SE angle.

## Notes to self
- The record types to mine: **A/AAAA** (hosts), **MX** (mail infra), **NS** (provider/zone), **TXT** (SPF + tech/service leaks), **CNAME** (aliases → stale targets).
- NS records feed zone-transfer attempts (`dig axfr`) and point at the provider.
- TXT records leak SaaS/tooling (`_1password`, `atlassian-domain-verification`, SPF `include:`) → OSINT + phishing.
