## DNS Zone Transfers

A zone transfer = wholesale copy of **all** DNS records in a zone from one name server to another (for replication/redundancy). If misconfigured, anyone can download the whole zone → every subdomain, IP, and record for free. Less invasive than brute-force.

## How it works (AXFR)
1. Secondary sends a zone-transfer request — type **AXFR** (full).
2. Primary replies with its **SOA** record (serial lets secondary check freshness).
3. Primary transmits **all** records (A, AAAA, MX, CNAME, NS, …).
4. Transfer complete signal → secondary **ACKs**.

## The vulnerability
- Early internet: any client could request a transfer → open hole.
- Leaks a full map: **all subdomains** (incl. dev/staging/admin not linked anywhere), their **IPs**, and **NS** records (provider + misconfigs).
- **Remediation:** modern servers only allow transfers to trusted secondaries. Misconfigs still happen → always try (with authorization).

## Exploiting
```bash
dig axfr @<nameserver> <domain>
# demo target that intentionally allows it:
dig axfr @nsztm1.digi.ninja zonetransfer.me
```
- Success = full record list printed. Note it uses **TCP** (port 53), not UDP.
- Don't know the NS? Get it first: `dig +short <domain> NS`, then `dig axfr @<that-ns> <domain>`.

## Notes to self
- For HTB boxes: find the domain (banners/scan), add it + its NS to `/etc/hosts`, then `dig axfr @<target> <domain>`.
- Count records quickly: `dig axfr @<ns> <domain> | grep -vE '^;|^$' | wc -l` (or filter to actual RR lines).
- Zone dump gives subdomains → feed straight into the rest of recon.

## Commands I actually ran (lab: zone transfer of inlanefreight.htb)
```bash
# full zone transfer from the target's name server
dig axfr inlanefreight.htb @<TARGET>

# Q1 - how many records were retrieved? count the actual RR lines
dig axfr inlanefreight.htb @<TARGET> | grep -E 'IN\s' | grep -vE '^;' | wc -l

# Q2 - IP of ftp.admin.inlanefreight.htb
dig axfr inlanefreight.htb @<TARGET> | grep 'ftp.admin'

# Q3 - largest IP in the 10.10.200.x range
dig axfr inlanefreight.htb @<TARGET> | grep -oE '10\.10\.200\.[0-9]+' | sort -t. -k4 -n | tail -1
```

### Notes to self
- Zone transfer uses **TCP/53**; just point `dig axfr` at the target (it's the authoritative NS here).
- To count records, strip comment lines (`^;`) and blank lines; the SOA appears twice (start + end) — decide whether the question counts it once or twice.
- `sort -t. -k4 -n` sorts IPs by the last octet to find the highest in a /24.
