## MSSQL

- Microsoft's closed-source relational DB, native to **Windows** (strong .NET support). Runs on Linux/Mac too, but expect it on Windows targets.
- Default port **TCP 1433** (SQL Browser on **UDP 1434** reports instances). Uses **T-SQL**.
- Auth can be **Windows Authentication** → login checked against local SAM or the domain controller (AD). A compromised DB account can enable **privesc / lateral movement** across the domain.

## Clients
- **Impacket `mssqlclient.py`** = the pentester's go-to (`/usr/bin/impacket-mssqlclient`).
- Others: SSMS (admin GUI — may hold **saved creds** on a compromised box), mssql-cli, SQL Server PowerShell, HeidiSQL.

## Default system databases
| DB | Purpose |
|---|---|
| `master` | all system/instance info |
| `model` | template for every new DB |
| `msdb` | SQL Server Agent jobs & alerts |
| `tempdb` | temporary objects |
| `resource` | read-only system objects |

> Real data is in the *non-default* databases — enumerate those.

## Dangerous settings
- Clients connecting **without encryption**.
- **Self-signed certs** when encryption is on (spoofable).
- **Named pipes** enabled.
- Weak/default **`sa`** account (admins forget to disable it).

## Footprinting
```bash
# NSE script sweep on 1433
sudo nmap -sV -p1433 --script ms-sql-info,ms-sql-ntlm-info,ms-sql-empty-password \
  --script-args mssql.instance-port=1433,mssql.username=sa,mssql.password= <TARGET>
```
Gives hostname, instance name, MSSQL **version/year**, named-pipe path.
```
# Metasploit alternative
msf6> use auxiliary/scanner/mssql/mssql_ping   # ServerName, InstanceName, Version, tcp/np
```

## Connecting (Impacket)
```bash
# Windows auth
impacket-mssqlclient <USER>@<TARGET> -windows-auth
# SQL auth (e.g. sa or found creds)
impacket-mssqlclient <USER>:<PASS>@<TARGET>
```
```sql
SQL> select name from sys.databases;   -- list all DBs
SQL> select @@version;                 -- version
SQL> use <db>; select * from <table>;
```

## Notes to self
- Version → year map: `15.00.x` = SQL Server **2019**, `14.0` = 2017, `13.0` = 2016.
- `ms-sql-ntlm-info` leaks domain/computer name even without creds — useful for AD footprinting.
- If `xp_cmdshell` is enabled with a high-priv login → command execution on the host.

## Commands I actually ran
```bash
# 1. hostname + version (NTLM info leaks the computer name w/o creds)
nmap -sV -p1433 --script ms-sql-info,ms-sql-ntlm-info 10.129.X.X
#   -> Target_Name / NetBIOS_Computer_Name = ILF-SQL-01 ; SQL Server 2019 (15.00.2000)

# 2. connect with found creds (backdoor:Password1)
impacket-mssqlclient backdoor:Password1@10.129.X.X                 # SQL auth -> "Login failed"
impacket-mssqlclient backdoor:Password1@10.129.X.X -windows-auth   # works -> ILF-SQL-01\backdoor

# 3. list databases, spot the non-default one
SQL> select name from sys.databases;
#   master / tempdb / model / msdb  (defaults) + Employees  <- target
```

### Notes to self
- Hostname comes from `ms-sql-ntlm-info` → `Target_Name` / `NetBIOS_Computer_Name`, no creds needed.
- **"Login failed" ≠ wrong password.** If SQL auth fails, retry with `-windows-auth` — the account is a Windows login (local SAM / AD), not a SQL login. Prompt then shows `HOST\user`.
- Non-interactive run: pipe the query, e.g. `printf 'select name from sys.databases;\nexit\n' | impacket-mssqlclient ... -windows-auth`.
