## SNMP — the essentials

- **Simple Network Management Protocol** — monitors *and* remotely configures network devices (routers, switches, servers, IoT). Runs over **UDP**.
- Ports: **161/UDP** = queries/commands (client → agent). **162/UDP** = **traps** (agent → client, unsolicited event notifications).
- For us it's an enumeration goldmine: if we can read it, it leaks OS, running software/versions, processes, network config, usernames and contact emails.

## Versions (what matters to an attacker)

| Version | Auth | Encryption | Takeaway |
|---|---|---|---|
| **v1** | none | none | Plaintext, no auth. |
| **v2c** | community string only | none | `c` = community-based. **String sent in cleartext → sniffable.** Most common in the wild. |
| **v3** | username + password | yes (pre-shared key) | Secure but complex; admins often avoid migrating, so v2c lingers. |

## Key terms

- **Community string** = effectively a password that gates read (or write) access. Default read string is almost always **`public`** (and sometimes `private` for write). Can be named anything, and can be bound to specific source IPs.
- **MIB** = Management Information Base: text file (ASN.1) describing *what* objects a device exposes, in a tree. It's the map, not the data.
- **OID** = Object Identifier: a dotted number (e.g. `.1.3.6.1.2.1.1.1.0`) that uniquely addresses one node in the MIB tree. Longer chain = more specific. `snmpwalk` shows these prefixed `iso` = `.1`.

## Dangerous misconfigurations (flag these in findings)

| Setting | Why it's bad |
|---|---|
| `rwuser noauth` | Full read/write to the whole OID tree, **no auth**. |
| `rwcommunity <string> <IPv4>` | Full tree access regardless of source IP. |
| `rwcommunity6 <string> <IPv6>` | Same, over IPv6. |

Config lives in `/etc/snmp/snmpd.conf`. `rocommunity public` = read-only `public` string → the typical soft target.

## Footprinting workflow

**1. Know the community string? Walk the whole tree:**
```bash
snmpwalk -v2c -c public <TARGET>            # dump everything
snmpwalk -v2c -c public <TARGET> <OID>      # one branch only
```
High-value OIDs to eyeball in the output:
- `.1.3.6.1.2.1.1.1.0` → OS / kernel banner
- `.1.3.6.1.2.1.1.4.0` → **sysContact** (often an email/username, e.g. `mrb3n@inlanefreight.htb`)
- `.1.3.6.1.2.1.1.5.0` → sysName (hostname)
- `.1.3.6.1.2.1.1.6.0` → sysLocation
- `.1.3.6.1.2.1.25.1.4.0` → boot line / kernel cmdline
- `.1.3.6.1.2.1.25.6.3.1.2` → installed software packages (version intel for exploits)
- `.1.3.6.1.2.1.25.4.2.1.2` → running processes
> A connection timeout usually means the wrong string or wrong version — try `public`/`private`, and both `-v1` and `-v2c`.

**2. Don't know the string? Brute-force it:**
```bash
sudo apt install onesixtyone
onesixtyone -c /usr/share/seclists/Discovery/SNMP/snmp.txt <TARGET>
```
A hit prints the string in brackets + the OS banner, e.g. `<TARGET> [public] Linux htb ...`.
> Strings are often named after the hostname with symbols added — `crunch` can build rule-based wordlists for big patterned networks.

**3. Have a string? Fast-enumerate OIDs with braa:**
```bash
sudo apt install braa
braa <string>@<TARGET>:.1.3.6.*     # syntax
braa public@<TARGET>:.1.3.6.*
```

## Notes to self
- SNMP is **UDP** — nmap it with `-sU` (`sudo nmap -sU -p161 <TARGET>`), easy to miss on a default TCP scan.
- First thing to try is always `snmpwalk -v2c -c public`. If that works, grep the dump for `.1.3.6.1.2.1.1.4.0` (contact) and `.25.6.3.1.2` (installed packages).
- No encryption on v1/v2c → the community string is sniffable on the wire; call this out in the report.
