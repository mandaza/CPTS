## Windows Remote Management

Three main protocols: **RDP** (GUI), **WinRM** (PowerShell/CLI), **WMI** (system mgmt). Remote mgmt on by default since Server 2016.

## RDP (TCP/UDP 3389)
- Microsoft's GUI remote access, TLS-capable but often **self-signed certs** (spoofable, cert warning). **NLA** (CredSSP) is the default auth layer.
```bash
# scan: NLA status, version, hostname (NTLM info)
nmap -sV -sC -p3389 --script rdp* <TARGET>
# unauth security-config check
./rdp-sec-check.pl <TARGET>
# connect from Linux
xfreerdp /u:<user> /p:'<pass>' /v:<TARGET>     # or rdesktop / Remmina
```
> `rdp-ntlm-info` leaks domain/computer name + build. **Nmap RDP cookie** `mstshash=nmap` is EDR-detectable — use `--packet-trace` awareness or avoid on hardened nets.

## WinRM (TCP 5985 HTTP / 5986 HTTPS)
- SOAP-based remote mgmt; powers PowerShell Remoting + WinRS. On by default since Server 2012. Usually only **5985 (HTTP)** is exposed.
```bash
nmap -sV -sC -p5985,5986 <TARGET>              # 5985 -> "Microsoft HTTPAPI httpd 2.0"
# PowerShell reachability: Test-WsMan <host>
# get a shell with creds (Linux)
evil-winrm -i <TARGET> -u <user> -p '<pass>'
```
> `evil-winrm` gives a full interactive shell — the go-to once you have Windows creds.

## WMI (TCP 135 → random high port)
- Read/write to almost all Windows settings. Accessed via PowerShell / WMIC / Impacket.
```bash
impacket-wmiexec <user>:'<pass>'@<TARGET> "hostname"   # or wmiexec.py
```
> Starts on 135, then DCOM moves to a random port — needs those high ports reachable.

## Notes to self
- All three leak the **hostname/domain** and give **command execution with valid creds** → prime targets after harvesting credentials.
- Order of preference with creds: `evil-winrm` (clean shell) → `wmiexec` → `xfreerdp` (GUI).
- Self-signed RDP cert = accept with `y` in xfreerdp; not a security barrier.
- WinRM `Microsoft-HTTPAPI/2.0` on 5985 is the tell-tale banner.
